# O1: scalar mutable traversal invariant

This is an experiment, not an accepted ownership summary. It runs independently
of count inference. Start from `46bb93564`; preserve the after-call candidate.
Only the native iterator-tail prerequisite is imported from `82d9f4fa9`, without
its wider migration or any claim that its history-based loop proof is bounded.

At function entry the caller transfers the slice's actual element predicates to
the verifier. Its entry value sequence E and length n are immutable observations.
The mutable reference slot has its own predicate and metadata. A logical element
index is not a physical address; zero-sized elements may share addresses.

Constructing IterMut transfers the original slice resource into an iterator-tail
resource and an owner-restoration obligation. The verification-only tail field
records a logical reference independently of raw pointer arithmetic. The pinned
Rust source uses a pointer plus remaining length for ZSTs; do not infer pointer
injectivity. This stdlib adapter is a trusted contract boundary, not a checked
implementation of split/join. Subsequent composition rules must be checked.

At loop head the target is Summary(owner, E, k, V): processed region [0,k), tail
[k,n), original-owner restoration obligation, and no outstanding yield. The
physical permissions belong to this summary. E and V alone grant no read of the
borrowed source. A successful next splits off one actual element resource; its
post-call tail snapshot must remain distinct from the entry and current snapshots.
Writing through the yield produces an updated value. Yield expiry returns that
resource; a checked join consumes the old summary and establishes a single new
summary with k+1. Iterator drop consumes the summary and restores the owner with
V. The summary must retain prefix values and untouched-suffix framing.

Initial scope rejects backedges with a live yield. Each rule has symbolic k,n,E,V,
explicit resource correspondence, and a checked body. No accumulated list of
completed-yield histories may cross the backedge. No fabricated future value,
permission, or unchecked function postcondition may stand in for a discharge.

First establish native constructor/next/drop positive and exact false/stale controls
using the existing contract. Then use a scalar prefix-update Rust client with
manual value invariants and a symbolic length; keep its suffix guarantee intact.
Measure generated bytes, loop invariants, wand instances and backend work before
and after the summary. A passing ownership-only traversal is a prerequisite,
not O1 success. The original reference-containing H1 pair remains unchanged.

## Concrete bounded value summary to test after transfer restoration

For scalar elements, the intended resource assertion is one wand:

```
Tail(current_tail) --* Owner(source)
    && values(source) == completed ++ before_expiry(values(current_tail))
```

`completed` is an immutable sequence captured by this particular wand instance.
It records final values of expired yields. The loop-head state contains only this
wand and the current tail resource; no yielded reference remains live. The pure
completed sequence is not permission to read source. At entry it is empty and the
constructor's original restoration wand establishes the assertion.

A checked symbolic join takes the old summary, the current next-restoration wand,
and the expired yield's actual resource/value. It packages a replacement summary
for the new tail: apply the next wand to reconstruct the previous tail, then apply
the old summary. The resulting value equality composes `completed`, the final
yielded value, and the new tail by sequence concatenation. The new summary captures
`completed ++ [final_yield_value]`. This is a proposed checked method body, not an
axiom. Its preconditions, sequence equality and permission correspondence must be
proved before native use. Preserve the original next and constructor contracts.

This formulation makes the size target explicit: one old summary and one step
wand consumed by each join, one new summary produced. Manual invariants describe
the completed sequence and unchanged tail. A later inference experiment may choose
constant-prefix templates over exactly these models; it must not change ownership
rules. First prototype the symbolic join and its false-value/missing-resource
controls, then connect it to native Rust. Standalone Viper success does not satisfy
O1. An observation of completed values requires the checked summary to exist.

introduced during associated-type normalization. Resolve only rustc's established
unifications before building the call region map. The resulting shape retains
both the yielded result and the post-call tail.

receiver temporary cleared the post-call region label on its historical

connection from the call's post-state to the live iterator, so restoration cannot

assertions are removed. Exhaustion additionally preserves the logical tail
reference, as the pinned std implementation returns before modifying it.
